# JAVA_RAG 文本 RAG 项目需求文档

版本：0.1（需求草案）　日期：2026-10-18　状态：待确认

> 本文记录项目最初的目标草案，技术栈和范围不等同于当前实现。当前实现以项目根目录的 README 和 `upstream/RagentAI/README.md`、`upstream/RagentAI/docs/项目说明.md` 为准。

## 项目目标
构建本地知识库问答应用。用户上传文本，系统解析、切分并生成向量写入 Milvus；提问时检索相关片段，调用大语言模型生成带来源的回答。MySQL 保存业务元数据和聊天记录。

## 技术基线
- Java 21 LTS，Maven Wrapper
- Spring Boot 4.1.x、Spring AI 2.0.x，通过 BOM 管理兼容版本
- MySQL 8、Milvus Standalone
- Spring AI 接入聊天模型、Embedding 和 Milvus VectorStore
- REST API；流式回答可采用 SSE
- 首期提供浏览器前端，包含用户对话界面和管理员知识库管理界面；前端框架待选型

### 模型选型
- 聊天模型使用 DeepSeek API，通过 Spring AI 的 OpenAI 兼容聊天模型接入。
- API 地址和模型 ID 均配置化；默认地址为 `https://api.deepseek.com`，模型 ID 默认 `deepseek-flash`，不要在代码中写死，方便按 DeepSeek 官方模型列表调整。
- 密钥通过 `DEEPSEEK_API_KEY` 环境变量提供，不提交到仓库或日志。
- Embedding 模型单独选型并配置；其 API 地址、模型 ID、向量维度应独立于聊天模型配置。Milvus 集合维度必须和 Embedding 输出匹配。

## 首期范围
首期提供可在浏览器使用的完整界面，包括用户对话和管理员知识库管理。用户可在选定知识库内提问并查看引用与会话记录；管理员可创建和维护知识库、上传 TXT/Markdown 文档并查看处理状态。首期按单管理员/单用户本地部署，不实现登录和多用户权限；PDF/DOCX、权限系统作为扩展项。

### 前端界面
- 用户对话界面：选择知识库，提交问题，查看回答及其来源引用，浏览会话历史；为后续 SSE 流式输出预留交互方式。
- 管理员界面：创建、重命名、删除知识库；上传 TXT/Markdown 文档；查看文档处理状态和错误；查看知识库中的文档并删除文档。
- 页面通过后端 REST API 读写数据；空状态、加载中、失败和无检索证据等情况应有清晰提示。

### 知识库与文档导入
- 创建、查询、重命名、删除知识库，查询文档及处理状态。
- 校验文件类型、MIME、大小；限制可配置。
- 保存文件名、大小、校验摘要、上传时间、状态及错误信息。
- 文本按可配置长度和重叠值切片；切片元数据包括知识库 ID、文档 ID、文件名、序号及可用位置。
- 处理状态为待处理、处理中、成功、失败；失败可重试。
- 重复文件策略可配置为拒绝或替换。
- 删除文档/知识库时清理原文件、MySQL 元数据和 Milvus 向量。

### RAG 问答与会话
- 选择知识库提问，在 Milvus 按知识库范围检索 Top-K；阈值、Top-K、提示词可配置。
- 将证据交给聊天模型；证据不足时明确说明，不伪造引用。
- 返回答案、引用文件/位置和会话 ID；聊天历史写入 MySQL。
- 会话绑定知识库；聊天记忆不作为知识库资料检索。
- SSE 流式输出为首期可选项。

### 运维与非功能
- 健康检查覆盖应用、MySQL、Milvus；记录导入失败和模型耗时，但不记录密钥。
- API 密钥只从环境变量或不入库的本地配置读取。
- 对上传大小、类型、参数、模型超时/限流/不可用统一校验和报错。
- 删除和跨库清理失败应可诊断并可补偿。

## API 草案
| 方法 | 路径 | 用途 |
|---|---|---|
| POST | /api/knowledge-bases | 管理端创建知识库 |
| GET | /api/knowledge-bases | 查询知识库（用户选择及管理端列表） |
| PATCH | /api/knowledge-bases/{id} | 管理端重命名知识库 |
| DELETE | /api/knowledge-bases/{id} | 管理端删除知识库 |
| POST | /api/knowledge-bases/{id}/documents | 管理端上传文档 |
| GET | /api/knowledge-bases/{id}/documents | 管理端查询文档和处理状态 |
| DELETE | /api/documents/{id} | 管理端删除文档和向量 |
| POST | /api/chat | 用户提问 |
| GET | /api/conversations/{id}/messages | 用户查询会话历史 |
| GET | /actuator/health | 健康检查 |

## 数据职责
MySQL 建议保存 knowledge_base、document、ingestion_job、conversation、chat_message。首期原文件存本地配置目录，数据库保存路径和摘要。Milvus 保存向量、切片和来源元数据。向量维度必须匹配 Embedding 模型；更换模型时重建向量或使用独立集合。

## 验收标准
1. 可创建知识库并上传 TXT/Markdown，查看处理状态。
2. 成功文档切片进入 Milvus；提问返回答案和来源。
3. 无证据时说明不足，不伪造引用。
4. 可查看会话历史并删除文档；删除后对应向量不再被检索。
5. 依赖服务异常时返回可诊断错误，仓库不包含真实密钥。
