# 当前项目架构

当前应用源码位于 `upstream/RagentAI`，以该目录作为 GitHub 仓库根目录。系统由 React/TypeScript 前端、Spring Boot 后端和数据库/向量检索/对象存储依赖组成。

## 主要请求流程

### 文档入库

管理员上传文档 → 后端校验和解析 → 文本清理与切片 → Embedding 服务生成向量 → Milvus 保存向量 → MySQL 保存知识库、文档、任务和分块元数据。原始文件由 S3 兼容对象存储保存。

### 问答

用户选择知识库并提问 → 后端按问题生成查询向量 → Milvus 相似度检索 → 组装检索证据及对话上下文 → DeepSeek 生成流式回答 → 前端展示答案和引用。

## 组件职责

| 组件 | 职责 |
|---|---|
| React 前端 | 登录、用户对话、管理后台、系统设置 |
| Spring Boot | 认证、REST/SSE API、文档处理、RAG 编排、模型调用 |
| MySQL | 用户、知识库、文档、任务、会话等业务数据 |
| Redis | 缓存和并发协调 |
| Milvus | 文本向量存储与相似度检索 |
| RustFS | S3 兼容文件存储 |
| DeepSeek | 聊天回答（`DEEPSEEK_API_KEY`） |
| 百炼 Embedding | 默认文本向量化（`BAILIAN_API_KEY`） |

聊天模型和 Embedding 是两种不同职责的模型能力；当前默认配置使用 DeepSeek 生成答案、百炼 `text-embedding-v3` 生成 1024 维向量。向量模型或维度改变时，应迁移/重建对应集合中的向量。

## 配置与安全边界

模型密钥通过后端环境变量读取，不应发送到浏览器。系统设置 API 只应暴露密钥是否已配置等状态。开发环境变量与真实密钥不得提交；部署时替换数据库、Redis、对象存储及管理员默认凭据。
